# 原生广告细节优化补充（v2）

## 🎯 优化目标

基于用户专业建议，针对以下 4 个关键细节进行优化，确保 Show Rate 达到 30-40% 目标：

1. ⚠️ **广告过期处理** (Ad Expiration)
2. ⚠️ **主线程 UI 渲染** (Main Thread Safety)
3. ⚠️ **Impression 监控** (Impression Tracking)
4. ⚠️ **崩溃和异常检查** (Crash Prevention)

## 🔧 细节优化 1: 广告过期处理（Ad Expiration）

### 问题描述

> AdMob 的原生广告对象通常在 **60 分钟后过期**。如果展示失效的广告，AdMob 不会统计 Impression，导致 Show Rate 虚高但实际收入为 0。

### 解决方案

#### 1.1 添加 CachedNativeAd 包装类

**文件**: `NativeAdManager.kt`

**实现**:
```kotlin
/**
 * 🆕 包装类：NativeAd + 时间戳
 * 用于跟踪广告加载时间，防止展示过期广告
 */
private data class CachedNativeAd(
    val ad: NativeAd,
    val loadTime: Long = System.currentTimeMillis()
) {
    /**
     * 检查广告是否过期（58分钟）
     */
    fun isExpired(): Boolean {
        val age = System.currentTimeMillis() - loadTime
        return age > AD_EXPIRATION_TIME_MS  // 58 * 60 * 1000L
    }
    
    /**
     * 获取广告年龄（分钟）
     */
    fun getAgeInMinutes(): Long {
        return (System.currentTimeMillis() - loadTime) / (60 * 1000)
    }
}
```

**关键常量**:
```kotlin
private const val AD_EXPIRATION_TIME_MS = 58 * 60 * 1000L  // 58 分钟
```

**为什么是 58 分钟？**
- AdMob 官方文档规定广告 60 分钟过期
- 预留 2 分钟缓冲时间，确保广告在展示前不会过期
- 避免"刚好 60 分钟"导致的边界问题

#### 1.3 定期清理过期广告

**实现**:
```kotlin
/**
 * 🆕 启动定期清理任务（5分钟一次）
 */
private fun startPeriodicCleanup() {
    Handler(Looper.getMainLooper()).post(object : Runnable {
        override fun run() {
            cleanupExpiredAds()
            // 下次清理
            Handler(Looper.getMainLooper()).postDelayed(this, CLEANUP_INTERVAL_MS)
        }
    })
}

/**
 * 🆕 清理过期广告（58分钟以上）
 */
private fun cleanupExpiredAds() {
    val expiredAds = cachedNativeAds.filter { it.isExpired() }
    
    if (expiredAds.isNotEmpty()) {
        Log.w(TAG, "⚠️ Found ${expiredAds.size} expired ads, cleaning up...")
        
        expiredAds.forEach { cachedAd ->
            cachedAd.ad.destroy()
            Log.d(TAG, "🗑️ Destroyed expired ad (age: ${cachedAd.getAgeInMinutes()} minutes)")
        }
        
        cachedNativeAds.removeAll(expiredAds)
        
        // 清理后如果缓存池变空，立即加载
        if (cachedNativeAds.isEmpty()) {
            loadNewAd()
        }
    }
}
```

**清理频率**: 5 分钟一次（配置: `CLEANUP_INTERVAL_MS = 5 * 60 * 1000L`）

#### 1.4 获取时自动跳过过期广告

**实现**:
```kotlin
fun getCachedAd(activity: Activity): NativeAd? {
    // ... (订阅检查) ...
    
    // ✅ FIFO: 取第一个广告，🆕 自动跳过过期广告
    while (cachedNativeAds.isNotEmpty()) {
        val cachedAd = cachedNativeAds.removeFirst()
        
        // 🆕 检查是否过期
        if (cachedAd.isExpired()) {
            Log.w(TAG, "⚠️ Skipping expired ad (age: ${cachedAd.getAgeInMinutes()} minutes)")
            cachedAd.ad.destroy()
            continue  // 跳过过期广告，继续取下一个
        }
        
        // ✅ 找到未过期的广告
        Log.d(TAG, "📺 Returning cached ad (age: ${cachedAd.getAgeInMinutes()} min)")
        return cachedAd.ad
    }
    
    return null
}
```

## 🔧 细节优化 2: 主线程 UI 渲染（Main Thread Safety）

### 问题描述

> `inflateView` 必须在主线程。如果缓存池管理在后台线程，务必确保 `setNativeAd` 操作回到 UI 线程，否则会造成 **0.9% 变 0%** 的惨剧。

### 解决方案

#### 2.1 NativeAdManager 确保主线程

**实现**:
```kotlin
fun getCachedAd(activity: Activity): NativeAd? {
    // 🆕 确保在主线程执行（UI 安全）
    if (Looper.myLooper() != Looper.getMainLooper()) {
        Log.w(TAG, "⚠️ getCachedAd called from background thread, switching to main thread")
        var result: NativeAd? = null
        Handler(Looper.getMainLooper()).post {
            result = getCachedAd(activity)
        }
        return result
    }
    
    // ... (后续逻辑) ...
}

fun loadAdWithCallback(activity: Activity, callback: (NativeAd?) -> Unit) {
    // 🆕 确保在主线程执行（UI 安全）
    if (Looper.myLooper() != Looper.getMainLooper()) {
        Handler(Looper.getMainLooper()).post {
            loadAdWithCallback(activity, callback)
        }
        return
    }
    
    // ... (后续逻辑) ...
}
```

## 🔧 细节优化 4: 崩溃和异常检查（Crash Prevention）

### 问题描述

> 优化不能影响产品功能体验。需要全面检查可能的崩溃点，确保稳定性。

### 解决方案

#### 4.1 广告销毁异常捕获

**实现**:
```kotlin
private fun cleanupExpiredAds() {
    expiredAds.forEach { cachedAd ->
        try {
            cachedAd.ad.destroy()
        } catch (e: Exception) {
            Log.e(TAG, "❌ Failed to destroy expired ad: ${e.message}")
        }
    }
}

fun destroy() {
    cachedNativeAds.forEach { cachedAd ->
        try {
            cachedAd.ad.destroy()
        } catch (e: Exception) {
            Log.e(TAG, "❌ Failed to destroy ad: ${e.message}")
        }
    }
}
```

---

#### 4.2 广告展示异常捕获

**实现**:
```kotlin
fun loadNativeAd(adTag: String) {
    try {
        nativeAd.setOnAdImpressionListener { ... }
        inflateView(nativeAd)
        NativeAdTimeUtil.saveTimeByTag(adTag, System.currentTimeMillis())
        reportEvent(adTag, "native_ad_shown", "success")
    } catch (e: Exception) {
        Log.e(TAG, "❌ Failed to display ad: ${e.message}", e)
        reportEvent(adTag, "native_ad_error", e.message ?: "display_failed")
        binding.root.gone()
    }
}
```

---

#### 4.3 inflateView 异常捕获

**实现**:
```kotlin
private fun inflateView(mNativeAd: NativeAd) {
    try {
        // 所有 UI 操作
        binding.root.visibility = View.VISIBLE
        // ...
        binding.nativeAdView.setNativeAd(mNativeAd)
        
        Log.d(TAG, "✅ Native ad inflated successfully")
    } catch (e: Exception) {
        Log.e(TAG, "❌ Failed to inflate native ad", e)
        binding.root.gone()
        throw e  // 向上传递异常，让外层捕获
    }
}
```

## 💡 关键洞察

### 1. 广告过期是隐形杀手

- 过期广告展示 Show Rate 看起来正常，但 **Impression = 0**
- **收入损失 5-10%**，而且完全不可见
- 解决方案：58 分钟自动过滤 + 5 分钟定期清理

---

### 2. UI 线程安全至关重要

- 后台线程调用 `setNativeAd()` **100% 崩溃**
- Show Rate 0.9% → **0%** 的惨剧
- 解决方案：所有 UI 操作强制主线程

---

### 3. Impression != onShow

- `onShow` 触发 ≠ AdMob 统计 Impression
- View 被遮挡、太小、不可见 → Impression = 0
- 解决方案：监控 `onAdImpression`，识别问题

---

### 4. 稳定性是底线

- 再好的优化，崩溃率上升 → 失败
- 用户体验 > 广告收入
- 解决方案：全面异常捕获 + 生命周期检查
