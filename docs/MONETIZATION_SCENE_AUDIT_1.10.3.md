# Quran Hub 广告与激励场景审计（1.10.3）

> 本文把“代码中已在线的展示点”和“待产品确认的建议”严格分开。建议项未在本次开发中启用。

## 已在线场景

| 格式 | 当前触发点 | 当前保护 | 结论 |
|---|---|---|---|
| 开屏 | 冷启动；应用回前台 | 首次安装冷启动仍跳过；订阅/买断去广告跳过 | 保留。不要在用户仍停留应用时重复模拟冷启动，也不要用于退出应用 |
| 插屏 | Quiz 结算结果渲染后 | 全局 3 分钟间隔、每会话 2 次、每日 5 次；订阅/买断跳过 | 保留，属于自然内容断点 |
| 插屏 | Quiz 关卡间继续 | 有预加载；无库存时全屏原生兜底 | 保留，但与全局频控口径需要继续统一检查 |
| 插屏 | 学习任务创建成功、返回首页前 | 全局频控；无广告立即继续导航 | 保留，属于完成态断点 |
| 插屏 | Qada Tracker 返回应用内上一页 | 全局频控 | 可保留；不得把 Activity 返回栈末端的“退出应用”当成该场景 |
| 原生 | 首页/VOTD、学习计划、Tafsir、Quiz 结果/关卡等容器 | 订阅/买断隐藏；缓存池优先、按需补池 | 保留，避免挤压正文和主要操作 |
| Banner | Wudu；Qada 周/月视图 | 订阅/买断隐藏；失败隐藏或原生兜底 | 保留，固定在内容边界，不覆盖按钮 |
| 激励 | Tafsir 高级内容解锁 | 用户主动点击“看广告”；完成奖励后解锁 | 保留，是当前最规范的价值交换 |
| 激励 | Quiz 重试/跳过 | 用户主动点击对应动作 | 保留，按钮需持续明确写出奖励 |
| 激励 | Tasbih 完成 33/99 次 | 当前完成轮次后直接调用广告 | **需整改**：改为完成卡片上的自愿领取奖励，不能把自动出现的广告称为激励广告 |

## 本次已经执行的策略调整

- 新用户插屏 24 小时全禁改为 0 小时；其他全局频控继续保留。
- 首次安装的首次开屏广告仍跳过，避免“内容出现前先展示全屏广告”。
- 不新增退出应用广告；退出应用仍不允许成为展示点。

## 待确认的插屏扩展（本次未启用）

优先级从高到低：

1. Quiz 每完成一个完整关卡组/结算页继续：建议启用，已基本存在。
2. 学习计划/任务创建成功后继续：首页返回前展示，已存在。
3. Qada 批量补记成功后离开结果页：建议可启用，但一天最多命中一次。
4. 完成一次完整 Surah 阅读后返回目录：谨慎；只在结果/完成卡之后，不得覆盖正文或诵读。
5. Wudu 教程完整完成后离开：谨慎；不在步骤切换中展示。

明确不建议：应用退出、经文阅读中、音频诵读中、Adhan 到点、礼拜时间查看、Qibla 校准、Tasbih 计数过程中。

## 待确认的激励扩展（本次未启用）

| 优先级 | 用户主动选择的奖励 | 建议时长/范围 | 原因 |
|---|---|---|---|
| P0 | 安静阅读：暂时去除非激励广告 | 60 分钟 | 价值清楚、即时、不可转让，最适合本品类；不影响订阅永久去广告价值 |
| P0 | 下载一个离线翻译包 | 单个语言包 | 与下载意图完全一致；基础在线翻译不能被锁死 |
| P0 | 下载一个 Tafsir/注释包 | 单个注释包 | 与已有 Tafsir 激励解锁衔接；每种语言至少保留一部免费权威 Tafsir |
| P1 | 下载一个诵读音频包 | 单个 Surah 或限量批次 | 数据成本与奖励价值匹配；在线播放仍可用 |
| P1 | Quiz 错题复习额外机会 | 本次复习会话 | 已有重试/跳过基础，用户理解成本低 |
| P1 | AI 学习计划一次深度解析 | 单次结果 | 必须先有普通免费结果，不能阻断核心计划能力 |
| P2 | 连续阅读统计的高级洞察 | 当日一次 | 不奖励或伪造宗教行为本身，只解锁分析展示 |

所有激励入口必须满足：用户主动选择、展示前明确奖励、可拒绝且仍可继续核心免费功能、只在完整观看并收到奖励回调后发放、奖励不可转让且不能兑换现金。

## 推荐的决策顺序

1. 先上线“去广告 1 小时”和“单个离线翻译/Tafsir 包”两个 P0 激励入口。
2. 同时把 Tasbih 自动激励改成完成卡自愿领取，避免政策与体验风险。
3. 插屏仅确认 P0 自然断点；正文、诵读和礼拜场景维持零打断。
4. 每个新场景固定上报 `request / loaded / shown / impression / reward / closed / no_fill`，上线后按场景看收益与退出率，不做触发策略 A/B。
