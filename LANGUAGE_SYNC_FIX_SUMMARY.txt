🐛 问题描述
═══════════════════════════════════════════════════════════════

用户反馈：当应用语言切换为印尼语时，经文翻译未同步切换，
仍然显示系统语言的翻译，导致用户体验不一致。

═══════════════════════════════════════════════════════════════
🔍 根本原因
═══════════════════════════════════════════════════════════════

经文翻译选择逻辑使用的是系统语言（Locale.getDefault()），
而不是应用内用户设置的语言（SPAppConfigs.getLocale()）。

❌ 问题代码：
   TranslUtils.defaultTranslationSlugs()
   └─> getSystemLanguage()  // 获取系统语言

✅ 正确做法：
   TranslUtils.defaultTranslationSlugs(context)
   └─> getAppLanguage(context)
       └─> SPAppConfigs.getLocale(context)  // 获取应用设置语言

═══════════════════════════════════════════════════════════════
✅ 修复方案
═══════════════════════════════════════════════════════════════

1. 新增方法：defaultTranslationSlugs(Context context)
   - 优先使用应用设置语言
   - 回退到系统语言

2. 新增辅助方法：getAppLanguage(Context context)
   - 封装语言获取逻辑

3. 更新所有调用位置（6 个文件）
   - ActivityReference.java
   - VOTDView.java
   - FragSettingsMain.java
   - SPReader.java
   - VotdReceiver.kt
   - ChapterInfoJSInterface.java

4. 标记旧方法为 @Deprecated
   - 保持向后兼容

═══════════════════════════════════════════════════════════════
📊 修复效果
═══════════════════════════════════════════════════════════════

修复前：
   应用语言: 印尼语 → 经文翻译: 英语（系统语言）❌
   
修复后：
   应用语言: 印尼语 → 经文翻译: 印尼语 ✅

支持的语言映射：
   • 印尼语 (id) → Kompleks Al Quran Raja Fahd
   • 英语 (en)   → Sahih International
   • 乌尔都语 (ur) → مولانا محمد جوناگڑهی
   • 阿拉伯语 (ar) → Sahih International（辅助）
